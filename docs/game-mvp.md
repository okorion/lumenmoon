# 게임 MVP 설계 계약

## 제품 정의

- 제품명: **루멘문(Lumenmoon)**
- 브라우저에서 짧게 즐기는 1인칭 비동기 공동 복셀 건축 게임이다.
- 동시 접속을 흉내 내지 않고, 앞선 플레이어의 결과를 다음 플레이어가 발견하고 이어 만드는 경험을 핵심으로 한다.
- MVP는 하나의 영속 월드를 사용한다. 모든 데이터는 향후 여러 월드를 지원할 수 있도록 worldId를 가진다.

## 확정된 게임 규칙

- 신규 플레이어는 최초 24블록을 받는다.
- 개인 베이의 첫 완성 가이드는 16블록, 생산시설 가이드는 8블록이다.
- 개인 베이와 생산시설은 소유자만 수정할 수 있다.
- 타인의 일반 블록 철거는 공용 자유 확장부에서만 허용한다.
- 공동 미션은 서버에 저장하는 원본 슬롯 24개를 4방향으로 시각 복제한다.
- 복제 블록은 별도로 저장하거나 기여도로 계산하지 않는다.
- 익명 계정은 변경 불가 공개 ID, 조합형 닉네임, 문양을 가진다.
- IP는 소유자 식별, 게임 데이터, 공개 UI에 사용하거나 저장하지 않는다.

## MVP에서 제외

- 실시간 플레이어 아바타와 위치 동기화
- 채팅과 자유 텍스트
- 전투, PvP, 경쟁 랭킹
- 거래와 현금성 재화
- 실시간 그림자, Bloom, 물리 파괴

## 1단계 구현 범위

- 로컬 1인칭 이동과 모바일 터치 조작
- 큐브, 계단, 조명 3종과 12색 팔레트
- 격자 배치, 회전, 자기 블록 제거
- 제작자 카드와 샘플 공동 월드
- IndexedDB 저장과 WorldRepository 추상화
- 16×16×16 청크, 가시 면 메시, 인스턴스 렌더링

## 2단계 로컬 첫 플레이 규칙

- 중앙탑 주위의 스타터 베이는 결정적 사각 고리 슬롯으로 배정하며 서로 겹치지 않는다.
- 베이는 제거할 수 없는 안전 스폰 발판, 중앙탑 방향 통로, 개인 영역 16칸, 생산시설 8칸으로 구성한다.
- 신규 플레이어는 24블록을 정확히 한 번 받는다. 첫 거점 완성 전에는 이 재고를 16+8 가이드에만 쓸 수 있다.
- 16칸과 8칸이 모두 현재 월드에 존재할 때 최초 1회 시운전 보상 2블록을 받는다.
- 두 가이드를 모두 완성하기 전에는 `내 베이 다시 시작`으로 자기 온보딩 블록만 지우고 최초 24블록 상태로 돌아갈 수 있다.
- 완성 뒤 개인·공동 건축과 생산 보상은 최대 36개인 단일 재고를 공유한다.
- 개인 16칸과 시설 8칸을 모두 완성한 시각부터 생산이 열린다. 생산시설 Lv.1은 마지막 정산 시각부터 3시간당 1개를 생산한다.
- 생산시설 가이드가 8칸보다 적어지면 생산은 멈추고, 8칸을 복구한 시각부터 다시 정산한다. 크론은 사용하지 않는다.
- 모바일 친화적인 3단계 수동 작업은 약 15초가 걸리고, 최근 24시간에 최대 3회 각각 1블록을 생산한다.
- 가동 중인 생산시설 주위 확장 가이드 12칸을 완성하면 Lv.2가 되며 자동 생산 간격이 2시간으로 줄어든다. 시설이 8칸 미만인 동안에는 확장 완성 정산과 해금도 보류한다.
- 시간은 교체 가능한 `Clock`, 수치는 `GameRulesConfig`로 주입한다.
- 데스크톱 Pointer Lock 중에도 `F`로 수동 생산, `X`로 미완성 베이 초기화를 실행할 수 있다.

## 2단계 로컬 권한 규칙

- 개인 베이와 생산시설은 해당 베이 소유자만 배치·제거할 수 있다.
- 중앙 공동 미션 예정 구역, 안전 스폰, 시스템 발판과 통로는 수정할 수 없다.
- 공용 자유 확장부에는 누구나 배치할 수 있다.
- 타인의 공용 블록은 같은 블록을 2.5초 연속 홀드해야 제거되며 재료를 주지 않는다. 중단한 진행률은 저장하지 않는다.
- 다른 블록의 `supportId`로 참조되는 블록은 먼저 위 블록을 제거하기 전까지 제거할 수 없다.
- 로컬 단계의 베이 슬롯과 진행 상태도 `WorldSnapshot.localState`에 저장한다. 저장소 계약은 그대로 유지해 이후 온라인 저장소로 교체할 수 있다.

## 3단계 비동기 공동 월드 규칙

- 저장소 모드는 `VITE_REPOSITORY_MODE=local|online`으로 반드시 명시하며 온라인 설정 실패를 로컬 월드로 숨겨 전환하지 않는다.
- 온라인 모드는 Supabase 익명 인증과 공개 `#XXXX` 태그·조합형 닉네임·문양만 사용한다. auth UID는 내부 관계 키로만 쓰고 RPC·공개 데이터에 노출하지 않으며, IP는 애플리케이션 테이블에 저장하지 않는다.
- 최초 프로필·24블록·스타터 슬롯은 `bootstrap_player`가 한 트랜잭션에서 배정한다. 월드별 사용자와 슬롯 양쪽에 고유 제약을 둔다.
- 주변 16×16 청크는 입장, 청크 이동, 탭 복귀 때만 읽는다. Realtime, WebSocket, 상시 폴링은 사용하지 않는다.
- 배치·제거·초기화는 최대 24개 action의 멱등 RPC로만 변경하며 좌표, 구역, support, 재고, 슬롯 소유권을 DB에서 다시 검증한다.
- 자동·수동 생산은 DB `now()`와 행 잠금을 기준으로 정산한다. 클라이언트 시각은 HUD 표시에만 사용한다.
- 타인 공용 블록은 서버 철거 티켓을 시작한 뒤 2.5초가 지나야 확정할 수 있다. 중단 시 티켓을 취소하고 보상은 지급하지 않는다.
- 온라인 배치는 서버 응답 전 반투명 미확정 블록으로만 보인다. 충돌·거절·네트워크 오류 시 bootstrap과 현재 주변 청크를 다시 읽는다.
- mutation 테이블의 직접 쓰기는 금지하고, 공개 프로필과 주변 청크 조회 및 검증 RPC만 authenticated 역할에 허용한다.

## 4단계 공동 미션 규칙

- 첫 템플릿은 `별빛 관문`이며 서버에 저장하는 정규 설계 슬롯은 층마다 24개다.
- 정규 원본 한 칸은 클라이언트에서 4방향 대칭 복제한다. 대칭축의 중복 좌표를 제거해 최대 96블록으로 보이지만 DB에는 원본 한 행만 저장한다.
- 원본 슬롯 확정만 기여도 1로 계산한다. 복제본과 미리보기는 저장하거나 기여도로 계산하지 않는다.
- 개인 거점 16칸과 생산시설 8칸이 현재 존재하는 플레이어만 단일 재고 1개를 사용해 기여할 수 있다.
- 활성 미션의 추천 가능한 미완성 슬롯은 최대 3개만 보여주며 사용자는 템플릿별 5색 팔레트에서 색을 고른다.
- 같은 슬롯의 동시 요청은 하나만 확정하고, 실패한 요청의 재고는 줄이지 않는다. 모든 기여는 actionId로 멱등 처리한다.
- 확정된 미션 원본과 그 시각 복제는 누구도 변경하거나 철거할 수 없다.
- 발광 체감 보상은 첫 기여의 5%부터 5·10·15…95·100% 단위로 증가한다. 이 값은 저장 기여 수에서 계산하는 시각 보상이며 별도 기여도로 계산하지 않는다.
- 6·12·18·24칸에서 각각 25% 바닥 문양, 50% 좌우 기둥, 75% 상단 고리·빛줄기, 100% 전체 발광·짧은 완성 연출을 연다.
- 24번째 기여 트랜잭션은 현재 층을 불변 기념물로 고정하고 다음 층의 활성 인스턴스를 정확히 하나 만든다.
- 다음 층은 같은 템플릿의 높이·회전·팔레트 시드를 바꿀 수 있으며, 인스턴스는 향후 다른 템플릿 ID도 참조할 수 있다.
- 현재 정수 월드 경계는 루멘문 약 4,680층까지 반복 가능하게 열어 두며, 그 이후 확장은 새 월드/수직 청크 정책과 함께 결정한다.
- 완료 시각과 모든 참여자의 고정 공개 ID·닉네임 스냅샷·문양·기여 수를 기록관에 보존한다. 내부 auth UID와 IP는 공개 응답에 포함하지 않는다.
- 조준 카드, 기여자의 빛, 미션 패널, 기록관에서 같은 공개 신원을 사용한다. 경쟁 순위는 만들지 않고 모든 참여자 문양을 같은 크기로 표시한다.
- 제작자 강조는 해당 제작자의 원본과 파생 대칭 복제본을 함께 강조하고 나머지를 잠시 반투명 처리하며 언제든 해제할 수 있다.
- 완료 연출은 Bloom·실시간 그림자 없이 emissive 색 변화와 제한된 파티클로 구현하고 즉시 건너뛸 수 있다.

## 4.5단계 저비용 제품 분석 규칙

- 제품 분석은 명시적으로 동의한 운영 환경에서만 PostHog Cloud로 전송한다. 개발·테스트 기본값은 `NoopAnalytics`이며 localhost와 E2E 실행은 외부 전송하지 않는다.
- 분석 이벤트는 `game_session_started`, `player_milestone_reached`, `game_session_summary`, `game_failure` 네 종류와 각 이벤트의 허용 속성으로 제한한다.
- 세션 리플레이, autocapture, 페이지뷰·이탈 자동 수집, dead click, heatmap, performance 자동 수집은 사용하지 않는다.
- Supabase auth UID, 공개 ID·닉네임, IP 속성, 정확한 좌표·블록 ID, 자유 텍스트, 전체 URL·query string, 원본 user agent, 토큰·환경 변수, 원본 오류·stack은 분석으로 보내지 않는다.
- 활성 시간은 문서가 보이고 최근 60초 안에 입력이 있었던 구간만 센다. 입력 스트림과 위치는 저장하지 않고 체류 구역만 개인·생산·미션·공용·기록관으로 합산한다.
- 5분 체크포인트와 종료 요약은 직전 전송 이후 델타만 사용하며 동일 `summary_sequence`를 재전송하지 않는다.
- 이벤트는 세션당 최대 20건, payload당 최대 4KB다. 고빈도 행동은 개별 전송하지 않고 세션 요약 카운터로만 합친다.
- Supabase에는 원시 분석 이벤트를 만들지 않는다. 실제 블록·철거·수동 생산·공동 기여처럼 DB가 확정한 운영 수치만 기존 RPC 트랜잭션과 함께 기록한다.
- 운영 집계 뷰는 `private` 스키마에 두고 `service_role`만 읽을 수 있다. 브라우저의 `anon`·`authenticated` 역할에는 조회·쓰기 권한을 주지 않는다.
- 분석 동의를 철회하면 즉시 `NoopAnalytics`로 전환하고 PostHog의 저장 식별자를 초기화한다. 자세한 개인정보·비용·대시보드 운영 계약은 `docs/analytics.md`를 따른다.
